# 本地数据、快照与恢复

## 数据位置

默认生产数据根目录是仓库下的 `studio-data`。它不会被 Git 跟踪。

- `projects/<projectId>/project.json`：项目元数据。
- `projects/<projectId>/chapters/*.md`：当前正式稿。
- `projects/<projectId>/chapters/.revisions/`：不可变章节修订及元数据。
- `projects/<projectId>/canon/`：角色、关系、世界书、时间线、伏笔、章后状态、事实索引和质量报告。
- `projects/<projectId>/theatre/`：角色剧场会话和全部分支。
- `runs/`：AI 生成请求、候选检查点和状态；不属于正式稿导出。
- `backups/<projectId>/`：在项目中心点击“创建本地快照”生成的项目目录快照。

开发服务默认使用 `studio/studio-data` 或测试专用目录；可用 `STUDIO_DATA_ROOT` 指定绝对路径。不要把数据根目录指向仓库根、用户主目录或云盘根目录。

## 日常备份

1. 在项目中心选择作品，点击“创建本地快照”。
2. 等待页面显示快照 ID 后再关闭服务。
3. 定期把整个 `studio-data` 目录复制到另一块磁盘。复制前先用 `Ctrl+C` 安全停止 `npm start`，避免刚好复制到原子替换过程中的临时文件。
4. Markdown/TXT/DOCX 是出版交付件；可迁移 JSON 是正式稿便携包。它们都不替代完整的 `studio-data` 备份，因为不包含剧场分支和修订历史。

系统保留最新操作快照，并按日/月保留恢复点。章节每次正式保存也会产生不可变修订；在小说工坊的“修订历史”中恢复会创建一个新修订，不会删除后来的历史。

## 恢复顺序

遇到异常时按破坏性最小的顺序处理：

1. 未保存正文：重新打开同一章节。只有当 IndexedDB 草稿的基础修订仍等于当前正式修订时才会自动恢复；旧草稿不会覆盖更新正式稿。
2. 章节误改：使用小说工坊“修订历史 → 恢复”。恢复本身会形成新修订。
3. 生成中断：候选检查点仍在 `runs/<runId>`，不要手工移动到 `chapters`。在支持恢复的运行上重新开始，或保留已生成片段作为候选。
4. 项目元数据损坏：停止服务，先复制整个 `studio-data` 作为现场副本，再从 `backups/<projectId>/<backupId>` 复制对应项目目录。不要在服务运行时覆盖目录。
5. 迁移失败：旧版导入先预览并核对指纹，应用时创建新项目，不会原地改写旧浏览器数据。删除失败的新项目副本前先保留快照。

如果不确定应恢复哪个目录，不要删除当前数据；把当前项目和候选备份都复制到新的临时位置后再比较 `project.json`、章节修订时间和质量报告引用的 revision ID。

## 移动到另一台电脑

1. 在旧电脑停止服务并复制完整 `studio-data`。
2. 在新电脑安装相同或更高版本的项目依赖并运行 `npm run build`。
3. 把数据放到新仓库的 `studio-data`，或用 `STUDIO_DATA_ROOT` 指向复制后的目录。
4. 单独在新电脑创建 `.env`。不要复制或分享包含真实密钥的日志、截图、仓库提交或导出包。
5. 运行 `npm start`，核对项目数、正式章数、字符数、未回收伏笔和最近修订后，再继续写作。

## API 密钥与安全停机

DeepSeek 密钥只放在根目录 `.env` 的 `DEEPSEEK_API_KEY`。`.env`、`studio-data` 和构建产物均不应提交。服务强制从 `127.0.0.1` 提供默认生产入口；不要使用端口转发、公共隧道或把监听地址改成局域网地址。

安全停机使用运行 `npm start` 的终端按 `Ctrl+C`，等待端口关闭。原子写失败时旧正式文件保持不变，新内容留在错误信息指向的 `.tmp` 恢复文件中；先保留该文件，再决定是否人工合并。
